# Настройка Vercel Blob для фотографий объявлений

## 1. Создать хранилище

1. Откройте проект AXION X в Vercel.
2. Перейдите в **Storage → Create Database → Blob**.
3. Создайте отдельное хранилище, например `axion-listing-images`.
4. Выберите **Public**: фотографии товаров должны загружаться браузером посетителя без авторизации. Не используйте это хранилище для документов, персональных данных или закрытых файлов.
5. Подключите хранилище к нужному Vercel-проекту и включите Production. Для Preview включайте его только если тестируете загрузку на preview-развёртываниях.

Vercel добавит переменную `BLOB_READ_WRITE_TOKEN`. Проверьте, что она доступна в Production Environment Variables. Не добавляйте префикс `NEXT_PUBLIC_` и не помещайте токен в клиентский код.

## 2. Установить зависимость и обновить lock-файл

Из корня проекта выполните:

```bash
npm install
```

В проект добавлен `@vercel/blob`. Команда синхронизирует `package-lock.json` с `package.json` и установит SDK. Затем проверьте:

```bash
npm run type-check
npm run build
```

## 3. Очистить старые локальные пути

Добавлена миграция `20261108143000_clear_legacy_listing_uploads`. Она удаляет из массива `listing.images` только неработающие ссылки `/uploads/...`; корректные Blob URL сохраняются.

Перед Production-развёртыванием примените миграции к базе данных:

```bash
npx prisma migrate deploy
```

Миграция не меняет структуру таблиц и не удаляет объявления, цены, остатки или другие данные.

## 4. Проверить загрузку

После деплоя войдите в админ-панель и проверьте:

- загрузку JPEG, PNG и WebP;
- ограничение 8 МБ на один файл и 10 фотографий на объявление;
- отображение фотографий в карточке каталога и на странице товара;
- создание нового объявления и редактирование существующего;
- отказ в загрузке для неавторизованного пользователя и пользователя без роли администратора.

Файлы отправляются из браузера напрямую в Blob. Сервер выдаёт краткоживущий токен только после проверки роли администратора; постоянный `BLOB_READ_WRITE_TOKEN` в браузер не передаётся.

## 5. Локальная разработка

Для локальной загрузки добавьте `BLOB_READ_WRITE_TOKEN` в `.env.local` (не коммитьте этот файл). Для тестирования callback `onUploadCompleted` на локальном компьютере Vercel рекомендует публичный HTTPS-туннель и `VERCEL_BLOB_CALLBACK_URL`; обычная загрузка через локальный сервер без callback остаётся возможной, но callback не сможет обратиться к `localhost`.
