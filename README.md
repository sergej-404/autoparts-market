# AXION_X_6_8

**Версия проекта:** AXION_X_6_8 (npm version 6.8.0). Следующие небольшие изменения оформляются как AXION_X_6_9.

## Изменения версии AXION_X_6_8

- Профиль: порядок вкладок «Статистика», «Мои заказы», «Партнерство», «Настройки»; боковая навигация закреплена на десктопе.
- На мобильных переключатели уведомлений выровнены справа от текста; удалено поле «Роль аккаунта».
- Добавлено подтверждение email и телефона PIN-кодом: 6 цифр, срок действия 2 минуты, блокировка на 1 минуту после 5 неверных попыток.
- Для доставки кодов настройте Resend (`RESEND_API_KEY`, `EMAIL_FROM`) и Twilio SMS (`TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER`) в `.env`.
- После изменения схемы примените миграции командой `npx prisma migrate deploy` и сгенерируйте клиент командой `npx prisma generate`.
- В настройках профиля добавлены разделы «Мои заказы», «Партнерство» и «Статистика» вместо ссылок на избранное, чат и уведомления.
- В раздел «Мои заказы» добавлены два явно обозначенных демонстрационных заказа из HTML-прототипа; они не связаны с базой данных.
- Боковая навигация закреплена при прокрутке на широких экранах.
- Добавлено подтверждение выхода из аккаунта; на мобильных устройствах кнопка выхода находится последним блоком настроек.
- На мобильных устройствах кнопки управления фото расположены справа от аватара в одной строке.

Стартовая версия интернет-магазина автозапчастей одного продавца.

## Примечания

- `base.db` содержит временные тестовые данные и не используется как постоянная база магазина.
- В `metadata` указан текущий публичный URL проекта. Перед сменой домена нужно обновить `metadataBase`.
- Обновление иконки/превью в поисковых системах происходит не мгновенно: после публикации поисковым роботам требуется повторно обойти сайт.

## Этап 3.1 — авторизация и PostgreSQL

Авторизация подготовлена на Better Auth + Prisma ORM + PostgreSQL. Для Prisma 6 используется классический клиент без дополнительного PostgreSQL-драйвера. Файл `base.db` остаётся нетронутым: он содержит временные тестовые товары и не мигрируется автоматически.

### Подключение базы

1. Создайте PostgreSQL-проект у облачного провайдера (например, Neon).
2. Скопируйте `.env.example` в `.env` (Prisma CLI читает этот файл).
3. Укажите `DATABASE_URL` из панели провайдера и задайте отдельный случайный `BETTER_AUTH_SECRET` (не публикуйте его).
4. Установите зависимости: `npm install`. При первой установке npm обновит `package-lock.json` для новых зависимостей (его не удалось пересобрать в среде подготовки из-за недоступности npm registry).
5. Примените миграции и сгенерируйте клиент: `npx prisma migrate deploy` и `npx prisma generate`.
6. Проверьте проект: `npm run type-check`.
7. Запустите приложение: `npm run dev`.

Локальный адрес приложения по умолчанию — `http://localhost:3000`. При другом адресе обновите `BETTER_AUTH_URL` и `NEXT_PUBLIC_APP_URL`.

### Что включено

- Регистрация по имени, email, телефону и паролю.
- Вход по email и паролю, выход управляется сессией Better Auth. На текущем шаге интерфейс входа принимает email; вход по телефону не включён.
- Уникальные email и телефон на уровне базы данных.
- Хеширование пароля и хранение сессий выполняет Better Auth.
- Подтверждение email и восстановление пароля пока не включены.
- Ошибки повторной регистрации, неверного пароля и ограничения частоты запросов отображаются на русском языке.
- Роль пользователя хранится в `user.role`; по умолчанию новая регистрация получает `USER`. Допустимые значения на этом этапе: `USER`, `MODERATOR`, `ADMIN`.
- Маршрут `/admin` доступен только роли `ADMIN`; `/moderator` — ролям `MODERATOR` и `ADMIN`. Доступ проверяется на сервере.
- После добавления роли примените новую миграцию командой `npx prisma migrate deploy`, затем выполните `npx prisma generate` и перезапустите сервер.
- Для назначения привилегированных ролей не используйте публичную форму регистрации: поле роли не принимается из клиентской формы. Назначайте `ADMIN` и `MODERATOR` только доверенным способом после проверки адресов пользователей.

Перед production-развёртыванием обязательно настройте секреты окружения, домен и HTTPS. Миграция добавляет только таблицы авторизации; таблица `products` из `base.db` остаётся в исходном SQLite-файле.


## Версия 6.0.0 — интерфейс сообщений

- На `/chat` добавлен адаптивный интерфейс списка диалогов и открытой переписки с поиском и фильтрами.
- Добавлены быстрые стартовые фразы, ввод до 250 символов, отправка демонстрационных сообщений, выбор изображения, меню жалобы и удаление диалога с подтверждением.
- Данные переписок пока демонстрационные и хранятся в состоянии клиентского интерфейса. Реальная доставка сообщений, хранение истории в PostgreSQL, загрузка изображений, жалобы и проверка доступа к конкретным диалогам не реализованы. Для следующего этапа потребуется спроектировать модели переписок/сообщений и серверные обработчики с проверкой владельца диалога.


## Предыдущая итерация — обновление интерфейса сообщений

- Страница `/chat` переработана по HTML-прототипу: заголовок с общим количеством диалогов, список из десяти демонстрационных диалогов, карточка контекста товара, адаптивная компоновка списка и переписки.
- Сохранены поиск и фильтры диалогов, индикаторы непрочитанных сообщений и статуса продавца, быстрые фразы, счётчик символов, прикрепление изображения, отправка демонстрационных сообщений, меню жалобы и удаление с подтверждением.
- Контекст обсуждаемого товара отображается для соответствующего диалога с тормозными колодками.
- Сообщения и список диалогов по-прежнему демонстрационные и хранятся в состоянии клиента. Реальная отправка/хранение, загрузка файлов, жалобы и серверная авторизация диалогов не реализованы.

## Изменения версии AXION_X_6_4

- Добавлена поддержка нескольких фотографий в одном сообщении (до 10 файлов, до 8 МБ каждый).
- Фотографии отображаются миниатюрами с горизонтальной прокруткой над полем ввода; просмотр позволяет увеличить фото и удалить выбранные до отправки.
- Сообщение с фотографиями можно отправить без текста. В переписке отображается ссылка «Просмотреть фотографии (N шт.)», а текст, если он есть, размещается отдельным абзацем.
- Галерея сообщения открывается поверх области истории переписки, не блокируя поле ввода.
- Фотографии читаются браузером в data URL и хранятся в состоянии демонстрационного интерфейса. Серверное хранилище/постоянная загрузка файлов пока не подключены.


## Изменения версии AXION_X_6_5

- Реализована страница `/profile/settings` в существующем стиле AXION X.
- Данные профиля загружаются из PostgreSQL для текущей авторизованной сессии; страница требует входа.
- Имя и фотография профиля обновляются через Better Auth. Изображение уменьшается в браузере перед отправкой.
- Email, телефон, роль, статус подтверждения и дата регистрации показываются из фактических данных аккаунта. Email, телефон и роль нельзя изменить из формы.
- Настройки темы, региона и переключатели уведомлений сохраняются локально в текущем браузере; они пока не синхронизируются с сервером.
- Демонстрационные заказы, сообщения, избранные товары и другие фиктивные данные в страницу не добавлены.
