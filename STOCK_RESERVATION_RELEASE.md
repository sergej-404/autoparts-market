# AXION X — резервирование остатков при создании заказа

## Новая логика

- Администратор задаёт `listing.quantity` как **доступный остаток**.
- При создании `PENDING` заказ и списание всех его позиций выполняются в **одной транзакции SERIALIZABLE**. Недостаток хотя бы одной позиции отменяет транзакцию целиком. Если остаток стал 0, статус объявления меняется на `OUT_OF_STOCK`.
- При `PENDING -> APPROVED` остаток не меняется.
- При `APPROVED -> COMPLETED` остаток не меняется.
- При `PENDING/APPROVED -> CANCELLED` администратором или `PENDING -> CANCELLED` покупателем количество возвращается один раз, в той же транзакции, что смена статуса. Если товар был `OUT_OF_STOCK`, возвращается `PUBLISHED`. `DRAFT` не публикуется автоматически.
- Удаление товара с незавершёнными заказами блокируется.
- Переходы из `CANCELLED` и `COMPLETED` запрещены, повторная отмена не добавляет остаток.
- Схема Prisma и миграции не менялись.

## ОБЯЗАТЕЛЬНО: переключение существующей БД

**Внимание:** старая версия списывала товар только при `COMPLETED` и считала `APPROVED` логическим резервом. Новая версия ожидает, что ВСЕ `PENDING` и `APPROVED` уже уменьшили `listing.quantity`.

Перед включением новой версии ОБЯЗАТЕЛЬНО завершите или отмените все заказы `PENDING` и `APPROVED` **на старой версии приложения**. Иначе новая отмена вернёт остаток, который не списывался, а завершение старого заказа не спишет товар. Историю `COMPLETED`/`CANCELLED` удалять не надо.

Проверка в Neon (ТОЛЬКО чтение):

```sql
SELECT status, COUNT(*) FROM "order"
WHERE status IN ('PENDING', 'APPROVED') GROUP BY status;
```

При отсутствии строк обе категории открытых заказов отсутствуют — можно переключить приложение. Если открытые заказы необходимо сохранить, не запускайте новую версию, пока не будет разработана одноразовая транзакционная конвертация для фактических заказов; запускать конвертацию вслепую нельзя.

Не выполняйте `prisma migrate reset`, `db push` или `migrate dev`: проблема с пятью историческими миграциями отдельно не решена, для данного изменения миграция не требуется.

## Проверки

1. Администратор создаёт опубликованный товар с количеством 5.
2. Покупатель заказывает 2: видимый остаток 3, заказ `PENDING`.
3. Покупатель отменяет: остаток снова 5, заказ `CANCELLED`; повторная отмена возвращает 409 и оставляет 5.
4. Новый заказ на 2, администратор одобряет и завершает: остаток остаётся 3 на обоих переходах.
5. Администратор отменяет другой `PENDING`/`APPROVED`: зарезервированный остаток возвращается.
6. Если товар в остатке 1 и два покупателя одновременно пытаются заказать по 1, успешен максимум один заказ.
7. Заказ нескольких товаров: если хотя бы одного недостаточно, не создаётся заказ и не уменьшается НИ ОДИН остаток.
8. После обнуления остатка карточка становится `OUT_OF_STOCK`, после отмены снова `PUBLISHED`.
9. Нельзя удалить товар, пока на него есть `PENDING` или `APPROVED`.
10. Проверить ручное изменение администратором `quantity` и статус `DRAFT` отдельно.

**Условия проверки:** на рабочем компьютере выполнить `npm install`, `npx prisma generate`, `npx tsc --noEmit`, `npm run build`; затем реальные интеграционные тесты на резервной БД. В текущей среде зависимости проекта отсутствуют, поэтому сборка не подтверждена.
