# Восстановление истории миграций Neon (без сброса данных)

Текущая схема Prisma соответствует показанной пользователем схеме Neon для таблиц приложения; таблица `email_otp_challenge` в базе остаётся нетронутой и приложением не используется. Столбец `phoneVerified` не требуется и не добавляется. Поля `phone` и `email` сохраняются.

В базе зарегистрирована миграция `20261014000000_email_otp`, которой нет в локальном каталоге. Это расхождение истории сохраняется и **не препятствует обычной работе Prisma Client**, но блокирует безопасный `prisma migrate dev`. Для полного восстановления найдите оригинальный `prisma/migrations/20261014000000_email_otp/migration.sql` в Git или старом архиве и восстановите его без изменений (Prisma сверяет checksum). Не создавайте выдуманный SQL и не удаляйте записи `_prisma_migrations`.

Не запускайте `prisma migrate reset`, `prisma migrate dev` или `prisma migrate deploy`, пока история не согласована. Используйте `npx prisma generate`, затем `npm run dev`. Перед изменениями Neon создайте резервную ветку.
