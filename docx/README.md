# AXION X — документация проекта

## Актуальный снимок проекта

Документация относится к исходникам архива `AXION_X_9_14_9` и текущей итерации подготовки интерфейса.

### Технологический стек

- Next.js `^16.4.5`, App Router.
- React / React DOM `19.2.0`.
- TypeScript `^5`.
- Tailwind CSS `^4.1.9`.
- Better Auth `^1.4.7`.
- Prisma / Prisma Client `^6.19.3`.
- PostgreSQL.
- Vercel Blob для публичных изображений объявлений.
- Web Push с VAPID.

Точные разрешённые версии зависимостей фиксируются в `package-lock.json`. Не обновляйте major-версии без отдельной проверки совместимости.

## Структура

- `app/` — страницы App Router и API routes.
- `components/` — интерфейсные компоненты, в том числе `components/layout/Footer.tsx` и `components/auth/AuthPage.tsx`.
- `lib/` — Better Auth, Prisma, авторизация, уведомления, работа с телефоном и вспомогательная серверная логика.
- `prisma/schema.prisma` — схема PostgreSQL.
- `prisma/migrations/` — миграции, присутствующие в репозитории.
- `public/` — статические ресурсы, иконки и брендовые изображения.
- `scripts/` — служебные скрипты.
- `docx/` — вся проектная документация Markdown.

## Основные команды

```bash
npm ci
npx prisma validate
npx prisma generate
npm run type-check
npm run lint
npm run build
```

Локальный запуск: `npm run dev`. Production-запуск: `npm run build` затем `npm run start`.

## Переменные окружения

Список-подсказка находится в `.env.example`. Основные секреты и подключения задаются только через локальный `.env` и переменные окружения Vercel:

- `DATABASE_URL` — PostgreSQL.
- `BETTER_AUTH_SECRET` — секрет Better Auth.
- `BETTER_AUTH_URL` — публичный URL приложения.
- `ADDITIONAL_TRUSTED_ORIGINS` — дополнительные доверенные origins, если необходимы.
- `BLOB_READ_WRITE_TOKEN` — токен Vercel Blob.
- `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — Web Push.

Фактический набор переменных сверяйте с `.env.example` и кодом. Не коммитьте `.env`, `.env.local`, API keys, токены и приватные ключи.

## Авторизация — подтверждённое состояние исходников

В текущей реализации используется Better Auth с email/паролем, минимальной длиной пароля 12 символов и дополнительным полем телефона. В `User` уже есть `emailVerified`, а Prisma-модель `Verification` используется инфраструктурой Better Auth.

**Важно:** в проверенном снимке исходников нет интеграции Resend, отправки шестизначного OTP, интерфейса ввода кода, обязательной проверки email перед созданием аккаунта или самостоятельного восстановления пароля. Это не следует считать работающей функцией только из-за наличия `emailVerified` или таблицы `Verification`.

Сведения об обнаруженной ранее базе Neon и миграциях, отсутствующих в репозитории, сохранены в `MIGRATION_RECOVERY.md`. Не удаляйте и не пересоздавайте таблицы базы без сверки с production.

Подробности и необходимые параметры для включения email-потока: `EMAIL_AUTHENTICATION_STATUS.md`.

## Подвал сайта

На мобильных экранах блок бренда должен оставаться над навигацией: название AXION X, описание, слоган, затем кнопки «Покупателям», «Помощь», «Контакты». Открытие одной секции не должно скрывать брендовый блок. На ширине от 768 px остаётся настольная трёхколоночная компоновка.

Пункты «Как оформить заказ» и «Связаться с нами» открывают информационные модальные окна. Ссылки «Регистрация» и «Вход» внутри окон ведут на `/register` и `/login`.

## Безопасность и выпуск

Перед публикацией:

1. Создать резервную копию PostgreSQL.
2. Проверить production-переменные окружения, не раскрывая секреты.
3. Выполнить `npx prisma migrate deploy` только после проверки набора миграций.
4. Выполнить `npm ci`, `npx prisma validate`, `npm run type-check`, `npm run lint`, `npm run build`.
5. Проверить регистрацию, вход, роли, корзину, заказ, чат, уведомления, загрузку изображений и Web Push.
6. Проверить мобильный и настольный интерфейсы на реальных устройствах.

Исторические release notes и отчёты аудитов сохранены в этой папке. Они описывают состояние на дату соответствующей итерации и не должны трактоваться как текущая конфигурация без проверки кода.
